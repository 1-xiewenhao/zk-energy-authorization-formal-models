# ProVerif models

Run `bash formal/proverif/run-proverif.sh` from the repository root. The
authoritative property list and exact RESULT selectors are in
`expected-results.json`. The runner checks all eight models and rejects missing,
ambiguous, unexpected, or unknown results, timeouts, and tool errors.

| Model | Expected outcome |
|---|---|
| `protocol-v2-auth-binding.pv` | 12 security/secrecy queries TRUE |
| `protocol-v2-settlement.pv` | Eight security/secrecy queries TRUE; one negated honest-reachability query FALSE with trace |
| `protocol-v2-compromise.pv` | Seven compromise-aware queries TRUE |
| `protocol-v2-auth-reachability.pv` | Negated honest-reachability query FALSE with trace |
| `mutants/protocol-v2-device-origin-bypass.pv` | Caller correspondence FALSE with trace |
| `mutants/protocol-v2-policy-version-unbound.pv` | Exact policy-version correspondence FALSE with trace |
| `mutants/protocol-v2-payer-provider-unbound.pv` | Payer/provider correspondence FALSE with trace |
| `mutants/protocol-v2-settlement-unkeyed-consume.pv` | Injective correspondence FALSE with trace; remaining control queries match the expectation table |

The last mutant is deterministically regenerated by `generate-mutants.mjs`.
Replacements are cardinality checked. The positive injective property is
preserved rather than weakened to a non-injective property.

The commitment-aware ideal relation
`verifyZk(zkProof(witness, secret, statement), statement, h(secret)) = ok`
abstracts proof-of-credential-secret possession conditional on knowledge
soundness. It does not establish the physical accuracy of sensor values.

Settlement single use is represented by a private exact-order keyed one-shot
process. Tamarin provides the complementary explicit linear-state analysis.
The complete assumptions and protocol mapping are in
`../../docs/model-specification.md`.
